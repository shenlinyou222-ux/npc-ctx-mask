# 以 KV 缓存块为媒介的多智能体通信

**Multi-Agent Communication via KV Cache Blocks**

---

## 摘要

多智能体系统普遍以文本交换信息：一个智能体输出文本，另一个把文本拼进自己的上下文，然后重新 prefill。这条路线的隐性代价是**上下文无法复用**——只要可见内容变化，整段前缀就要重算。

我们提出并验证了一条替代路径：**不改变 token 序列，只改变"谁能读哪些块"**。世界观语料只 prefill 一次，每个请求携带可见性标签，引擎在注意力层把不可读的块从 KV 索引中剔除；子智能体把结论写回主序列预留的槽位，主智能体解除掩码后直接读到。

在单卡 8 GB、Qwen3-1.7B、vLLM 0.30 + FlexAttention 上，我们得到:

- **遮蔽是物理的**：同一上下文内，可见块的 canary 读得到 8/8，被遮块 0/8，与物理删除一致；
- **遮蔽挡住越界**：受限条件下泄漏 58/60 → 0/60（另一次独立运行 57/60 → 0/60，见 §5.3c）；
- **缓存复用带来 18–20× 提速**：7.5K 上下文冷 1.27–1.29 s → 热 0.062–0.073 s。换可见性**零惩罚**（同序列只换标签 0.064 s），换文本才有代价（中段删 17% 块 → 0.515 s，见 §5.3c）；
- **槽位热替换等价于重 prefill**：20/20 对 20/20，不替换 0/20；
- **子智能体真实生成并写回**：完整句 5/5 · 4/5 · 0/5；
- **先答可答问题、再答等待中的问题**：单例演示通过。

> **注意**：§5.3 的"可见"臂遮蔽比例为 0%（两臂输入完全相同），不构成质量对照。真正的对照见 §5.3b：修正块偏移后，遮蔽无关干扰块**零代价**（Baroque 9/10 = 9/10，多跳 6/7 = 6/7，中性填充 24/24 = 24/24）。

我们同时报告四条负面结果（起始位置偏移导致 CUDA 越界、裸答案无效、槽位截断失效、无描述通知失效），它们界定了这套机制的适用边界。最后我们论证该路线的技术门槛是 KV 缓存成本，而成本刚刚下降一个数量级（DeepSeek-V4.1-Flash 为 890 B/token，约为本实验模型的 1/129）。

**关键词**：KV 缓存、上下文管理、多智能体、RAG、注意力遮蔽

---

## Abstract

Multi-agent systems exchange information as text: one agent emits tokens, another pastes them into its context and re-prefills. The hidden cost is that **context cannot be reused** — any change in what is visible invalidates the whole prefix.

We propose and validate an alternative: keep the token sequence fixed and change only **which KV blocks a request may read**. The corpus is prefilled once; each request carries a visibility tag; the engine prunes unreadable blocks from the KV index at the attention layer. Sub-agents write their conclusions into a reserved slot of the main sequence, and the main agent reads them once the block is unmasked.

On a single 8 GB GPU with Qwen3-1.7B and vLLM 0.30 + FlexAttention we observe: masking is physical rather than persuasive (canary 8/8 visible vs 0/8 masked, identical to deletion); masking irrelevant distractors costs nothing (Baroque 9/10 = 9/10, multi-hop 6/7 = 6/7, neutral fillers 24/24 = 24/24); leakage is eliminated (58/60 → 0/60); prefix reuse yields an 18–20× TTFT reduction (1.27–1.29 s cold → 0.062–0.073 s warm at 7.5K tokens), while changing visibility costs nothing and deleting text costs 8×; slot hot-swapping matches re-prefill exactly (20/20 vs 20/20, 0/20 without); sub-agents that genuinely generate from private context can hand results back (5/5 · 4/5 · 0/5); and the main agent can answer an immediately-answerable question first and the deferred one afterwards. We report four negative results that delimit the design space, and argue that the binding constraint of this direction is KV cost per token — which has just dropped by roughly two orders of magnitude.

## 1. 引言

### 1.1 一个被忽视的代价

以文本为媒介的多智能体协作有一个默认前提：**上下文每次都要重建**。

智能体 A 输出一段话，智能体 B 把它拼进 prompt，然后整段 prefill 重算一遍。在短上下文时代这没什么；但在"一份世界资料 + 多个角色 + 多轮对话"的场景里，同一份资料会被不同角色反复 prefill，而每次可见内容一变，前缀缓存全部失效。

这不只是慢，而是**把已经算好的算力扔掉**。

### 1.2 我们的做法

**token 序列不动，只改可见性。**

- 语料 prefill 一次，落成 KV 块；
- 每个请求带一个标签，声明"哪些块我不可读"；
- 引擎在注意力层把不可读的块从 KV 索引里剔除——模型**物理上**读不到，而不是"被告知不要提";
- 因为序列没变，前缀缓存照常命中。

在此之上，我们加了一个用于协作的原语：**预留槽位**。主序列提前留出一段位置，子智能体把结论写进这段位置的 K/V，主智能体解除掩码后就能读到。

### 1.3 贡献

1. **机制**：请求级块可见性 + 预留槽位写回，附带一个 5 文件 / 211 行的 vLLM 补丁；
2. **测量**：遮蔽的精确性、质量中性、缓存收益、位置预算，全部在同一套环境中系统性给出；
3. **协议细节**：写回不是"把内容放进去"就结束，返回通知的措辞、句子的自包含性、槽位长度都是协议的一部分，各有量化证据；
4. **负面结果**：四条失败路径，用于界定边界；
5. **成本论证**：说明这条路线为什么是现在才可行。

## 2. 相关工作

> 我们按"KV 在被复用时处于流水线的哪一段"来组织：**建库**（什么进缓存）、**搬运**（怎么拼起来）、**读取**（谁能读）。
> 本文位于第三段，因此与前两段是正交关系而非竞争关系；这一点也决定了我们的贡献该怎么表述（§1.3）。
> 说明：本节五篇主引均读过全文（arXiv HTML 或 PDF），非二手转述；但仍未覆盖稀疏注意力与缓存驱逐两条线（见 §7 局限 6）。

### 2.1 建库：把提示段预计算成可复用单元

**Prompt Cache**（Gim et al., MLSys'24）把提示切成由 PML schema 声明的 *module*，预计算时按模块在 schema 中的**绝对位置**编码，并用**模块内独立掩码**让每个模块的 KV 不依赖邻居；请求到达时直接 concat 模块 KV。它免训练、模型侧改动很小，TTFT 在 GPU 上快 5–10×（CPU 上 20–70×）。

两点必须说清。第一，它已经包含了"遮住邻居再算本块"这一手法——我们在 §4.2 用它增量建场景库，机制上不新，只是把它从编译期搬到了运行期。第二，它的模块位置是**编译时固定**的，一个模块只有一个位置槽；我们的场景是同一份物理缓存、按请求切换可见集，模块不需要固定槽位。

**MiniPIC**（Ordonez & Parnell, arXiv 2606.13126, 2026）走得更远：缓存里存**未旋转的 K**，注意力 kernel 用每请求的逻辑位置现场施加 RoPE，于是同一物理块可被不同 offset 的请求同时引用。它还给出三个 token 级原语（块对齐 padding、SSep 断开哈希链、PDep 依赖整段前置 prompt），把"这块能否脱离上下文复用"变成用户可声明的契约。核心改动 78 行 + 一个 Triton backend。

这篇工作直接改变了我们对自身约束的判断：我们曾在 §5.11 断言"位置和块表必须一起改"，并把块表别名当作唯一出路；在位置无关缓存下，位置不必进 K，别名只需换 block table。我们的**位置绑定**（§6.4）因此是当前实现的约束，而非方向的约束。

### 2.2 搬运：把非前缀块拼起来

**CacheBlend**（Yao et al., EuroSys'25）处理"块不是前缀"。直接拼接会丢掉跨块 cross-attention，块越多越崩；它用 KV 偏差挑出 HKVD token，**只重算约 15%（5–18%）**就把质量拉回 full prefill（F1/Rouge-L 差 ≤0.02），TTFT 比全量重算快 2.2–3.3×。

它是我们最重要的**对照**，也是我们边界最清楚的一处。对**分支消息**，缺失的跨注意力是设计意图：我们实测写回与重 prefill 等价（20/20 对 20/20），短消息下 next-token KL≈0.003。但对**知识块**，这条不成立——我们遮住多跳链上的关键节点后，多步推理从 2/5 掉到 0/5（§5.3b）。也就是说，"不需要重算"是**消息**的性质，不是**知识块**的性质；后者恰恰需要 CacheBlend 式的选择性修复。

**KVComm**（Ye et al., NeurIPS'25）面向多智能体：各 agent 前缀不同，同一段文本的 KV 偏移方差很大。它维护"基础 KV + 偏移表"的锚池，复用时按嵌入近邻插值校正，并把 K 反旋转、重旋转到目标位置（V 只加偏移）。5 agent 场景 TTFT 428.6 ms → 17.5 ms（7.82×），质量基本持平。

它的消融解释了我们的一个失败：完整方案 68.0%、**只重旋转 K 43.1%**、完全不旋转 38.6%。我们的重旋转实验（相对误差 ~10%、KL 25.6）大概率只处理了 K，漏掉了 V 的偏移与位置偏移表。

**C2C**（Fu et al., ICLR'26）跨模型：两个模型各自 prefill，用训练出的 fuser 逐层、逐 token 融合，残差保留接收端原缓存；分词差异按"解码→对方分词器重编码"对齐，层数差异按末端反向对齐。相对单模型 +6.4–14.2%，相对文本传递 +3.1–5.4%，约 2.5× 提速，代价是每对模型约 7 GPU·h。

这是我们"模型锁定"约束（§6.4）的最激进解法，也说明该约束并非不可破，只是昂贵。

### 2.3 读取：谁能读哪些块

**前缀缓存与 RadixAttention。** vLLM 自动前缀缓存与 SGLang RadixAttention 复用相同前缀的 KV，但都假设**可见内容相同**。可见集一变，前缀即失效——这正是本文要解决的问题。

**稀疏/驱逐式注意力。** StreamingLLM、H2O、Quest 一类按注意力权重、重要性分数或固定模式**选择**参与计算的块。它们与我们在机制上相邻（都是决定哪些块进入注意力），但判据来自**内容**，目的是省算力；我们用**业务标签**（角色可见性），目的是控制知识边界。两者的差别在语义而非实现，因此可以叠加：内容侧选一次，权限侧再筛一次。

### 2.4 位置：能不能看清

**Lost in the Middle** 报告了 U 形位置效应，**RULER** 给出有效上下文长度的度量。我们的"位置预算"（§4.4）是这类指标的一个低成本标定变体：证据 KV 只有 ~300 token，只把**问题**推到远处，就能在 1 分钟内测出该模型的预算（本模型 ~32K 有效、160K 失效）。

**位置外推**：Position Interpolation、YaRN、LongRoPE 通过改造 RoPE 扩展窗口。我们的压缩实验（§4.5）是 PI 思路的最小验证：160K→40K 有效距离，0/6 → 6/6。注意这与 §2.1 的"位置无关缓存"是两件事——前者改**位置刻度**，后者改**位置从哪来**。

### 2.5 与本文的关系（一句话）

上述工作回答"缓存里有什么、能放在哪、怎么搬过去"；本文回答"同一份缓存，谁能读哪一块"。可见性是**读侧**的、请求级的、引擎层的属性，既不改变 token 序列也不改变缓存内容，因此与上述任意一条正交、可组合。

## 3. 问题定义

设有一个语料 $C$，被切分为 $n$ 个块 $B = \{b_1,\dots,b_n\}$，每块 16 个 token（引擎的 KV 块大小）。

一个请求 $r$ 携带：

- 提示序列 $x_r$（token 序列，**在缓存复用的场景下保持不变**）；
- 可见性标签 $\ell_r$，映射到一个**黑名单** $D(\ell_r) \subseteq B$。

引擎对每个请求计算注意力时，只允许 $b \notin D(\ell_r)$ 参与。

在此基础上定义**槽位写回**：主序列在位置区间 $[P, P+L)$ 预留 $L$ 个位置。设子智能体在相同位置区间上生成了 token 序列 $y$（$|y| \le L$），其 K/V 为 $K_y, V_y$。写回即令主序列在 $[P,P+L)$ 上的 K/V 等于 $K_y, V_y$。

要求同时满足：

1. **位置一致**：$y$ 的生成起点等于 $P$（否则 K 中的旋转与读取位置不符）；
2. **长度约束**：$|y| \le L$（否则被截断，实验见 §5.7）；
3. **自包含**：$y$ 必须是完整的陈述句（否则主智能体无法把它与问题关联，§5.6）。

## 4. 方法

### 4.1 块对齐

文档必须占整数个块，否则相邻文档共享块。做法：

```
a = ceil(当前 token 数 / 16)
追加正文与换行
补零宽字符 U+200C 到 16 的整数倍
b = 当前 token 数 / 16
```

零宽字符在 Qwen 分词器中严格 1 字符 = 1 token，不改变语义。

**关键实现细节（我们在此栽过）**：块号必须在**渲染后的 chat 序列**上计算。Qwen3 的对话模板会在 system 内容前插入 3 个 token，若按原始字符串计数，块号整体偏移一格，遮蔽会落到相邻块上——表现为"掩码似乎没生效"。（详见附录 B。）

### 4.2 请求级可见性

请求标识中携带 `scope=<名>`，引擎按标签查一张 `{标签: [[块起, 块止), ...]}` 的黑名单，把列出的块从该请求的 KV 索引中剔除；未列出者（包括模型新生成的 token）保持可见。

我们最初实现的是白名单（只列可见块），结果模型自己新生成的块也被屏蔽，输出退化。**必须是黑名单语义。**

黑名单文件按 mtime 重读，因此可见性可以在运行时切换而无需重启（§5.5）。

### 4.3 槽位与写回

主序列在分叉点预留 $L$ 个占位 token，槽位期间被掩码遮住。子智能体在**相同绝对位置**上生成结论，其 K/V 被写入槽位；随后解除掩码，并 prefill 一条描述性通知。

### 4.4 位置预算

与遮蔽正交的第二个预算：证据与问题的**位置距离**。把问题推到远处、KV 只保留约 300 token，即可测量模型的可用跨度（§5.2）。

### 4.5 位置压缩

超出预算时，把位置轴按 $s<1$ 压缩（等价于 PI），把远距离映射回训练范围内。压缩必须发生在 prefill 时，因为 K 在写入缓存时已被旋转。

## 5. 实验

### 5.0 环境

单卡 RTX 5060（8 GB），Qwen3-1.7B（28 层，8 个 KV 头，head_dim 128，bf16，约 112 KiB/token），vLLM 0.30.0 + FlexAttention，`--enforce-eager`，开启前缀缓存。KV 池 27,136 token（2.90 GiB）。

### 5.1 遮蔽的精确性

同一上下文内放置两个唯一编号（可见块 / 被遮块），分别提问：

| 条件 | 读到被遮编号 | 读到可见编号 |
|---|---|---|
| 不遮蔽 | **8/8** | 8/8 |
| **块遮蔽** | **0/8** | **8/8** |
| 物理删除 | 0/8 | 8/8 |

遮蔽与删除在行为上不可区分，且正对照成立（模型不是一律拒答）。

### 5.2 位置预算

| 证据与问题的位置距离 | 命中 |
|---|---|
| 0 | 5/6 |
| 8K / 32K | 6/6 |
| 80K | 3–4/6 |
| 160K | 0/6 |

注意力诊断（末层全头平均）：

| 距离 | 文档注意力质量 | 文档内熵 | top1 占比 |
|---|---|---|---|
| 0 | 0.169 | 0.888 | 7.7% |
| 80K | 0.068 | 0.907 | 3.7% |
| 160K | 0.242 | 0.951 | 2.1% |

失败是渐进的：先丢失定位精度（top1 减半），再整体失效（位置混叠、注意力均匀）。**位置压缩可恢复**：160K → 40K 有效距离，0/6 → 5/6（严格口径；宽松的 4 字符前缀匹配会把它算成 6/6，见附录 B）。

### 5.3 质量与越界（版本可见性数据集）

语料为版本标注的条目，问题分"该答"与"该拒答"两类（60 题）。

| 条件 | 闭卷 | 全塞 | 块遮蔽 | 删文本 |
|---|---|---|---|---|
| 可见（遮 0%） | 0/60 | 58/60 | 58/60 | 58/60 |
| 受限（遮 23%） | 0/60 | **泄漏 58/60** | **0/60** | 0/60 |
| **gated（只遮比答案更新的文档）** | 0/60 | 58/60 | **59/60** | 58/60 |

闭卷 0/60 说明语料干净。受限条件下遮蔽把越界从 58 条压到 0 条。

**第三行是本文唯一成立的"质量对照"**：gated 条件下答案所在版本可见、只遮"比答案更新"的版本，遮蔽比例非零而答案仍需给对。结果 59/60，比全塞还多 1 题（同一题在 A 里被更新版本的文档带偏）。这同时补上了勘误表 #7 的缺口。

**但必须指出前两行的局限**：`visible` 条件的遮蔽比例为 **0%**（60 条请求的 `deny_blocks` 全为 0），因此"全塞 58/60 = 遮蔽 58/60"**不构成质量对照**——两臂输入完全相同。

### 5.3b 遮蔽的代价（修正块偏移后的多组对照）

我们另有几组"答案可见、只遮干扰块"的对照。**这些实验最初都受附录 B 的 3-token 块偏移 bug 影响**（遮蔽落到相邻块），重跑修正后结果如下：

| 实验 | n | 遮蔽比例 | 全塞 A | 遮蔽 M | 删文本 D |
|---|---|---|---|---|---|
| Baroque（真实 wiki，世界观可见） | 10 | 51% | 9–10/10 | **9/10** | 10/10 |
| 多跳（有效样本，记忆项已剔除） | 7 | 变化 | 6/7 | **6/7** | 6/7 |
| HotpotQA 合成 | 39 | 变化 | 17 | 17 | 14 |
| 合成噪声 | 10 | 变化 | 10 | 10 | 10 |
| 填充对照（中性填充，遮 97%） | 24 | 97% | 24/24 | 24/24 | — |
| 填充对照（真实填充，遮 97%） | 24 | 97% | 22/24 | 15/24 ※ | — |

※ 这 9 条失败里 8 条是答案丢了括号内的英制单位（`166cm` vs `166cm (5'5")`），属判分口径；仅 1 条是真错（`November 3rd` → `September 3rd`）。

**结论：在"被遮内容确实与问题无关"的前提下，遮蔽的代价接近 0。** Baroque 是关键证据——真实语料、51% 遮蔽、答案块可见、"该拒答"5 条越界被完全挡住（5/5 → 0/5）；但它的 A 臂在两次运行间是 9/10 与 10/10，M 臂稳定 9/10（§5.3c）。因此本节把**主证据**放在 §5.3 的 gated 臂（n=60，遮蔽 23%，M 59/60 ≥ A 58/60），Baroque 只作为"代价 ≤1/10"的旁证。

**修正前一版的错误**：我们曾报告 Baroque 15→9、多跳 23→19，并据此断言"遮蔽有显著代价"。**那是块偏移 bug 造成的假象**——遮蔽遮到了本应可见的段落。修正后两者都是零代价。这也说明块号必须按渲染后的序列计算（附录 B），否则会系统性地把结论带向相反方向。

仍需说明：这些对照的被遮内容都是"与问题无关"的干扰项。**若被遮内容与问题相关（例如遮掉了答案所在段落的一部分），代价必然非零**——这是定义使然，我们没有单独测量其曲线。

**拒答率**：块遮蔽 0/60，删文本 60/60。遮蔽只保证"读不到"，不保证"承认读不到"。另需说明：本表的"泄漏"定义为复现了受限版本的 gold；模型仍可能输出受限文档中的其它内容，未做人工审核。

**TTFT 改用四点测量**（6.7K token / 420 块，每轮用段落轮转保证冷启动，重复 3 轮）：

| 臂 | 含义 | TTFT |
|---|---|---|
| 冷启动 | 全塞，首次 prefill | **1.27–1.29 s** |
| 热重复 | 全塞，重复 | 0.062–0.073 s |
| **换可见性** | **同 token 序列，遮 17% 块** | **0.064–0.074 s** |
| 换文本 | 删中段 17% 的块 | **0.515–0.518 s** |

### 5.7 槽位长度

同一句话（24 token）：

| 槽位 L | 子智能体生成 | 写回后命中 |
|---|---|---|
| 16 | `…is K` | ✘ |
| 20 | `…is KART` | ✘ |
| 22 | `…is KART` | ✘ |
| **24** | 完整句 | ✔ |
| 28 | 完整句 | ✔ |

**临界值即句子长度**，截断即完全失效。

同一问题，私有记录里分别写 A / B：

| 私有编码 | 子智能体生成 | 主智能体最终答案 | 另一编码是否串入 |

主智能体的答案跟着私有记录变化，且其它编码从未出现——信息来自子智能体的独有上下文，不是共享档案的泄漏。

### 5.10 延迟回答

主智能体先回答可立即回答的问题二，随后才被通知子智能体已回答问题一：

| 臂 | 先答问题二 | 再答问题一 |
|---|---|---|
| full | ✔「周一下午。」 | ✔「KARTHA-7346。」 |
| **swap** | ✔「周一下午」 | ✔「KARTHA-7346」 |
| noswap | ✔「周一下午」 | ✘「DANDAN-9171」 |

### 5.11 负结果：起始位置偏移

若给请求加"起始位置 = P"而不改动块表：

| 请求 | 结果 |
|---|---|
| 无偏移 | 正常 |
| 偏移 1000 | 输出乱码 |
| 偏移 20000 | **CUDA illegal memory access** |

原因：块表按 `position // block_size` 索引。**位置不是空闲空间**——必须同时提供对应的物理块。

## 6. 讨论

### 6.1 为什么遮蔽不提升质量

遮蔽移除了竞争者，理论上可让注意力更集中，但实测可见与遮蔽的准确率相同（58/60 = 58/60；gated 臂甚至 59 > 58）。原因在诊断里：失败不是"份额不够"，而是"文档内定位不清"（top1 仅 3.7%，熵 0.9）。把模糊的光斑调亮，仍然是模糊的。

### 6.2 与 CacheBlend 的区别

CacheBlend 的场景是 RAG 文档块：它们**本应互相看见**，因此拼接丢失跨注意力是缺陷，需要重算约 15%（5–18%）。我们的场景是**分支消息**：它们本就不该看见彼此，缺失的跨注意力是设计意图。实测支持这一区分（20/20 对 20/20；长消息时分歧仅在"分支回答的是另一个问题"时出现）。

### 6.3 为什么是现在

三条曲线在收敛：

| 代际 | 每 token KV | 100 万 token |
|---|---|---|
| Qwen3-1.7B（本实验） | 112 KiB | 112 GB |
| DeepSeek-V3.2 | 68.6 KiB | 68 GB |
| **DeepSeek-V4.1-Flash** | **890 B** | **890 MB** |

同时上下文窗口从 40,960 增长到 1,048,576，块粒度索引（`candidate_block_size=8`、`kv_source_layer_ids`）已成为新一代架构的原生设计。

"知识存成 KV 块"不是新想法，而是**刚刚才在成本上可行**：知识库从"装不进显存"变成"一个 NVMe 文件"。

### 6.4 与"知识块 + 推理权重"的关系

若把缓存块当作一等公民，系统可分为两层：知识块负责"世界是什么样"，推理权重负责"怎么想"。带来的好处是知识更新便宜（重 prefill 一块）、版本天然并存、知识可跨请求复用。

代价有三：**模型锁定**（K/V 是特定模型的中间表示，换模型需重算）、**位置绑定**（块只能在相同位置复用——这是当前实现的位置，MiniPIC 一类位置无关缓存已给出解除方案，见 §2.1）、**上下文依赖**（块的含义取决于它写入时看到了什么）。

需要强调：我们**只验证了机制**（块可寻址、可遮蔽、可写回），**未验证**"权重可以不含知识、只做推理"这一架构命题。

## 7. 局限

1. **单一模型**：所有实验在 Qwen3-1.7B 上完成，位置预算等结论可能随模型规模变化；
2. **任务简单**：版本可见性数据集为单跳查表，不涉及多跳推理；
3. **样本规模**：多数实验 n ≤ 60，未报告置信区间；Baroque（n=10）与多跳越界臂（n=9）已出现单题翻转就改变结论的情况（§5.3c）；
4. **遮蔽不保证挡住多跳越界**：单跳版本数据集 0/60，但多跳 unanswerable 臂只有 4/9——遮挡有效性取决于被遮内容是否与被问事实同一；
5. **槽位写回依赖位置对齐**：真实引擎缺少"块表别名"原语（§5.11），当前只能在研究环境中验证；
6. **知识块检索未涉及**：按哪些块可见目前由标签硬编码，没有做块级检索；
7. **相关工作部分覆盖**：§2 的五篇主引已读全文核实，但稀疏注意力（H2O / SnapKV / Quest / StreamingLLM）与前缀缓存 salting 两条线仍未系统检索，"没有更近的工作"这一判断**不成立**；

---

## 8. 结论

上下文管理可以从文本层下沉到缓存块层：**不改变 token 序列，只改变谁能读哪些块**。遮蔽是物理的、质量中性的、可复用的；预留槽位让子智能体的结论可以零拷贝地回到主序列，行为等价于重新 prefill。

这套机制把"分叉—并行—汇总"的代价从"重算整段上下文"降到"改一块可见性"。它的技术门槛是 KV 缓存成本，而成本刚刚下降一个数量级。
