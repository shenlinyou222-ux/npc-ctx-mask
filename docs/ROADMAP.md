# 还需要什么：样本多样化清单

> **独立审查（见 `docs/ERRATA.md`）确认：本文目前最缺的不是"更多样本"，而是三条能支撑核心主张的对照。**
> 其中第 0 条是阻断级：**"保留答案块、遮蔽 23% 干扰块"的真对照尚未做**。

## 第 0 优先级（阻断，必须先做）

| 缺口 | 为什么是阻断级 |
|---|---|
| **真遮蔽对照**：gold 可见、只遮 23% 干扰块 | 现有 ZZZ 实验的"可见"臂遮蔽比例为 0%，两臂输入相同，"遮蔽不损质量"无证据 |
| **filler 的 22→15 需要解释** | 严格判分下真实填充掉 7 条（8 条是格式截断、1 条真错），必须统一判分后重测 |
| **槽位三组实验落盘** | §5.4、§5.8–5.10 无 JSON，不可复算 |
| **统一判分口径** | 完整子串 vs 前缀匹配混用，是多数数字偏差的根源 |

> 现有数据只能支撑"机制可用"这一层结论。要让结论站得住，下面这些是缺口。

## A. 任务类型

| 缺口 | 为什么要 | 怎么补 |
|---|---|---|
| **多跳推理** | 现在全是单跳查表（身高/生日），不涉及跳转 | 用 MuSiQue / 2WikiMultiHopQA 的 comparison 子集（hops 独立，适合并行分支） |
| **需要综合的任务** | 现在答案在一句话里，槽位放一句就够 | 多文档摘要（Multi-News）：每个分支摘要一篇，合并 |
| **对抗性干扰** | 没测过"会真的把模型带偏"的段落 | 构造与正确答案矛盾的干扰块，看遮蔽是否提升准确率（这是我们唯一没验证的正面收益） |
| **多轮对话** | 现在的交互是一轮问答 | 连续多轮，槽位反复复用，看是否有状态残留 |

## B. 规模与统计

| 缺口 | 现状 | 目标 |
|---|---|---|
| 样本量 | 多数实验 n ≤ 60 | ≥ 200，报 95% 置信区间 |
| 显著性 | 裸数字对比 | McNemar / Fisher |
| 重复 | 单次运行 | 至少 3 个随机种子 |

## C. 模型

| 缺口 | 现状 | 目标 |
|---|---|---|
| 位置预算 | 只有 Qwen3-1.7B | 2–3 个不同规模/不同 rope 配置的模型 |
| 槽位写回 | 只有 1.7B | 至少一个大模型（看"接受外部结论"的能力是否随规模变化） |
| 架构差异 | 只有 GQA | MLA 类架构（块共享/压缩）上的表现未知 |

## D. 语言与领域

| 缺口 | 现状 | 目标 |
|---|---|---|
| 语言 | 英文为主，中文只做了单例 | 中英各 200 题 |
| 领域 | 单一游戏世界观 | 至少再加一个（技术文档 / 医疗 / 法律之一） |
| 长文档 | 单块级事实 | 跨块事实（需要多块协同） |

## E. 机制层面还没测的

| 项 | 说明 |
|---|---|
| **多槽位并行** | 现在只有 1 个槽位；真实场景要 3–5 个分支同时写回 |
| **槽位复用** | 同一槽位被多轮复用后，旧内容是否残留 |
| **块表别名** | 引擎原语未实现（见 `docs/block-alias-design.md`） |
| **块级检索** | 现在"该解除哪些块的掩码"是硬编码标签，没有检索 |
| **位置压缩与掩码的组合** | 两者都测过，但没在同一请求里同时用 |

## 优先级建议

```
P0（影响结论成立）: A.多跳 / A.对抗性干扰 / B.样本量≥200 / C.第二个模型
P1（影响可用性）  : E.多槽位 / E.槽位复用 / D.中文
P2（影响泛化）    : D.领域扩展 / E.块级检索
```
