# 上下文掩码 + 位置预算：工程经验 v1

> 结论都对应本仓库的实测，编号见 §5。模型：Qwen3-1.7B + vLLM `FLEX_ATTENTION`，RTX 5060 8GB。

---

## 1. 两个正交的预算

掩码和位置是**两件独立的事**，各有自己的预算，不能互相替代：

| | 解决什么 | 预算 | 超预算的后果 |
|---|---|---|---|
| **掩码** | 能不能看（安全 / 计算） | 无观察到上限（0–97% 都试过） | 没有质量代价 |
| **位置跨度** | 看不看得清（注意力精度） | **模型相关，本模型 ~32K，40K 上限** | 先丢精度（答格式对、值错），再整体崩 |

一句话：**掩码管"读不读"，位置管"清不清"。**

---

## 2. 位置预算怎么测（标定流程，1 分钟，不吃显存）

不需要真的塞 32K/80K token。只要把**问题推到远处**，KV 始终只有 ~300 token：

```
序列 = [系统提示 + 证据 ~200 token] + [问题 ~20 token]
position_ids = 证据 0..L-1，问题 L+gap .. L+gap+q
gap ∈ {0, 8K, 32K, 80K, 160K}
```

实测（6 条事实，纯距离、无竞争者）：

| gap | 命中 | 状态 |
|---|---|---|
| 0 | 5/6 | 正常 |
| 8,000 | 6/6 | 正常 |
| 32,000 | 6/6 | 正常 |
| 80,000 | 3–4/6 | **精度衰减**（`August 06, 2025` 这种格式对、值错） |
| 160,000 | 0/6 | **位置混叠**（`The The The`） |

**判据**：命中率跌破 90% 的那个 gap，就是该模型的位置预算。

> 为什么可以这样测：注意力只看**相对位置**。把问题推到 80K 外，与把证据放在 80K 上下文的开头，对 q·k 来说是等价的几何关系。

---

## 3. 超预算时怎么办

| 手段 | 效果 | 注意 |
|---|---|---|
| **压缩位置轴**（PI，`pos × s`，s<1） | 160K 间隙压到 40K 有效距离：**0/6 → 6/6** | 必须在 prefill 时压（K 在写缓存时已旋转） |
| 放大位置（s>1） | ❌ 崩（s=4 输出 `(((((`） | 反方向，衰减更重 |
| 重排/重锚（非单调位置） | ❌ 崩（输出乱码） | 违反因果顺序 |
| 物理搬近（压缩上下文/重排） | ✅ 最稳，24/24 | 改 token 序列，前缀缓存失效 |

**压缩率经验**：把有效距离压到预算以内即可，本模型 160K→40K（s=0.25）从 0/6 回到 6/6。

## 4. 掩码侧的工程规则

| 规则 | 依据 |
|---|---|
| 掩码比例随便调，没观察到质量代价（24% / 51% / 97% 都试过） | 22/24 = 22/24；9/10 vs 10/10；58/60 = 58/60 |
| 掩码**不改 token 序列** → 前缀缓存照常命中：冷 1.27 s → 热 0.062 s（18–20×）；**换可见性 0 惩罚**（0.064 s），换文本 8× 代价（中段删 17% 块 → 0.515 s） | 2026-10-28 四点测量 |
| 块必须**自己占满整数块**（不足补零宽字符），否则相邻块共享 | 块区间验证 |
| **不要**指望掩码让模型说"不知道" | M 拒答 0–1/6，D 拒答 5–6/6 |
| **不要**指望掩码提升准确率（除非干扰是误导性的，未验证） | 随机干扰下 M ≈ A |

## 6. 已知未验证 / 有风险的点

1. **"掩码提升质量"没证实**：只测过随机干扰，没测误导性干扰（会真的把模型带偏的段落）。
2. **位置预算只测了一个模型**：1.7B。大模型/长训练模型应该更大，但没测。
3. **KV 重旋转**：理论上可精确改已缓存 K 的位置（旋转叠加律），但我的数值验证还没通过（相对误差 ~10%），未定论。
4. **压缩位置会压扁块间顺序**：细粒度排序任务可能受损，未测。
5. **80K 真实上下文**没跑过（显存不够），只有位置间隙模拟。
