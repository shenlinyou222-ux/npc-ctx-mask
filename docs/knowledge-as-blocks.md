# 知识块 + 推理权重：把"记忆"从参数里搬出来

## 命题

如果把上下文缓存块当作一等公民，那么系统可以拆成两层：

| 层 | 负责 | 形态 |
|---|---|---|
| **知识块** | 记住"世界是什么样" | 预先算好的 KV 块，按标签寻址，同级并存 |
| **推理权重** | 负责"怎么想" | 模型参数，只做组合、比较、推断 |

权重不再需要把大量事实压进参数里；事实住在块里，需要时被"解除掩码"读进来。

## 这个拆分带来的三件事

**1. 知识更新变便宜**

改一条事实 = 重新 prefill 那一块（几秒），不需要微调，也不需要重训。我们已经在版本可见性数据集上做过：同一个角色在 2.0 / 2.4 / 2.7 / 3.2 各有一份可见集，切版本只是换掩码。

**2. 版本与视角天然并存**

同一份世界，不同时间点、不同角色，可以是**同一批块的不同可见子集**——这正是我们掩码在做的事。知识不再只有"一个训练时刻的快照"。

**3. 知识可以跨请求复用**

只要模型相同，块就是可共享的：N 个请求共享一份 prefill，命中缓存。我们的 TTFT 0.98s → 0.06s 就是这个性质的直接体现。

## 三个硬约束（我们实测或推导得出）

**① 模型锁定**

K/V 是特定模型的中间表示。Qwen 的块给不了 Llama，换模型就得全部重算。
**文本是模型无关的，KV 不是。** 这是这条路最大的代价。

**② 位置绑定**

块里的 K 带着写入时的位置旋转。所以块只能在"相同位置"复用，否则要重旋转（我们的数值验证未通过）。
位置预算也在这里起作用：证据离问题超过约 32K（本模型）就开始丢精度。

**③ 上下文依赖**

块的 K/V 取决于它生成时看到了什么。CacheBlend 的结论是"拼非前缀块会掉质量，要重算约 18%"。
我们的场景不同——分支消息本来就是独立产生的，不需要互相看见——但这条约束对"知识块"是真实存在的：**把两段互不相干的知识拼在一起，模型可能读不出它们的关系**。

## 一个量化：这条路是被缓存成本解锁的

存 100 万 token 的知识，需要多少空间？

| 模型 | 每 token KV | 100 万 token | 能不能放 |
|---|---|---|---|
| Qwen3-1.7B（本实验，GQA） | 112 KiB | **112 GB** | ❌ 不现实 |
| DeepSeek-V3.2（MLA） | 68.6 KiB | 68 GB | ❌ |
| **DeepSeek-V4.1-Flash** | **890 B** | **890 MB** | ✅ 一个 NVMe 文件 |

所以"知识存成 KV 块"不是今天才有想法，而是**刚刚才变得可行**：每 token 成本降了 129 倍，知识库从"装不进显存"变成"能放在硬盘上流式读取"。

这也解释了为什么这套机制值得现在做——它卡在成本曲线上，而曲线刚刚拐过去。

## 我们验证了什么、没验证什么

**验证了（机制层）**：

- 块可以被请求级地遮蔽 / 解除，且是物理上的读不到（canary 0/8）；
- 遮蔽不损质量（57/60 = 57/60），并挡住越界（57/60 → 0/60）；
- 一块的 K/V 可以按位置写回另一条序列，行为等价于重 prefill（20/20 = 20/20）；
- 子智能体可以带着私有上下文生成结论，主智能体读得到，且读不到共享档案里没有的东西（noswap 反证）。

**没验证（架构层）**：

- "权重可以完全不含知识、只做推理"——我们没有做这个实验，也无法用 1.7B 证明；
- 知识块跨会话、跨用户的共享与失效策略；
- 块级检索（怎么知道该解除哪些块的掩码）——目前是硬编码的标签。

## 一句话

> 参数负责"怎么想"，块负责"知道什么"；两者在同一段地址空间里并存，靠可见性而不是靠拼接来组合。
> 这条路的技术门槛是缓存成本，而缓存成本刚刚降了一个数量级。
