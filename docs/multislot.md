# 多槽位：答案重新 prefill 成 K/V，换回空白掩码块

## 机制

```
① 主序列（前缀 + 空槽位 + 问题）先 forward，K/V 进缓存
② 子智能体在自己的上下文里得到答案
③ 答案 token 只对 [0, P_k) 的缓存做 prefill → 得到 [P_k, P_k+len) 的 K/V
④ 这段 K/V 换进空槽（后缀不重算）
⑤ 解除掩码，之后 decode
```

**效果**：等价于"当时问了子智能体，答案立刻就在那里"。

## 结果

| NS | swap（K/V 换回） | inline（内联重算） | empty（不填） |
|---|---|---|---|
| 3 | 11/12 | 12/12 | 0/12 |
| 5 | **15/15** | 15/15 | 0/15 |
| 合计 | **26/27** | 27/27 | **0/27** |

- `swap` 与 `inline` 基本持平（26/27 vs 27/27），说明**换回来的 K/V 与原生内联等价**；
- `empty` 全错，且会编造（`is 1234` / `is 12345`）。

## 为什么这条能成，之前那条不能

| 做法 | 结果 |
|---|---|
| 搬**子智能体算好的** K/V（它在自己位置上生成的那份） | ❌ 位置对不上；用 position_ids 覆盖 → 0/5 |
| **把答案重新 prefill** 到目标位置 | ✅ 26/27 |

差别在于：前者要求"生成时就落在那个位置"，后者只是"在目标位置重新算一遍"。
后者不需要任何位置技巧，因为 prefill 天然按缓存长度续位。

等价性不是巧合：解除掩码后，decode 的每个 token 用自己的 query attend 所有 ≤ 它的 key，
包括刚填进来的块。写入早晚不影响可读性，只看 query 出在掩码解开之前还是之后。

## 代价

每个槽位只多做 **len(answer) 个 token 的 prefill**（约 20–32 token），
前缀和后缀都不重算。这是引擎侧的一次前向，与模型侧无关。
