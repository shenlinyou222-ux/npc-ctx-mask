# 可行性测试：长上下文池化 + 块级稀疏 decode + 重紧凑

模型 Qwen3-1.7B（bf16），单卡 8 GB，上下文约 1.7K token（刻意压低避免 OOM）。

## 一、重旋转实现是否正确

`scripts/recompact.py`：拦截 `apply_rotary_pos_emb` 取**旋转前**的 K，按目标位置重新旋转。

| 检查 | 结果 |
|---|---|
| 用未旋转 K 重算，是否等于 HF 自己算的旋转后 K | **最大逐元素误差 0.000e+00** ✔ |
| 整段平移 1000 后，注意力分数是否不变（fp32 旋转） | 绝对差 **9.4e-04** ✔ |
| 同上，**bf16 旋转** | 绝对差 1.34，**相对差 32%** ✘ |

**结论：重旋转必须用 fp32**，否则远位置会严重漂移。K 可存 bf16，但旋转时升 fp32 再降回。

## 二、提取 + 重紧凑的端到端等价性

池 = 内容全集、选中全部 → 与直接前向的 `max|Δlogits| = 0.125`（bf16 噪声量级）。
池更长、只取前 41 个 token → 同样 `0.125`。

**说明提取与重旋转本身是无损的**，后续退化不是实现 bug。

## 三、查找类：池化可用

上下文 = `S0 + 块A(编码) + 填充800 + 块B(编码) + 填充800 + 问题`，问 A 的编码。

| 臂 | 命中 | 每次请求 |
|---|---|---|
| full（全部可见） | **12/12** | 0.400s |
| **pool_A（池里取 S0+块A，重紧凑）** | **12/12** | 0.073–0.12s |
| pool_B（故意取错块） | 1/12 | 0.073s |

**质量与全上下文持平，单请求快 3–5 倍。**（池只建一次，0.34s）

**踩过的坑**：最初只取块 A、漏了 S0，掉到 6/12——因为问题格式指令在 S0 里。S0 必须一起选。

## 四、推理类（比较）：池化失效

问「谁进球更多」，选项是两个人名——**必须同时看到两块才能判断**。

| 臂 | 命中 | 每次请求 |
|---|---|---|
| full（全上下文 468 token，含 400 填充） | **14/20** | 0.106s |
| fresh（只 prefill S0+A+B） | **20/20** | 0.070s |
| **pool_both（池里取两块 + 重紧凑）** | **18/20** | 0.152s |
| only_A（只看 A） | 10/20 | 0.061s |
| only_B（只看 B） | 10/20 | 0.049s |

**结论：池化 + 重紧凑对比较类成立（90%），不需要对选中集重新 prefill。**
而且 `only_A`/`only_B` 都只有 50%，证明这道题确实需要两块，没有捷径。

注意 **full 只有 70%**：1600 token 的无关填充把注意力稀释了。
去掉填充、压紧位置（pool_both 90%、fresh 100%）反而更好。

### 前一次的结论是错误的（已作废）

上一版问「A 是否比 B 进球多」，选项是 yes/no。**模型只看 B 块也能答对**——
因为真值一半是 "no"，看到 B 的高分就能靠偏置蒙对。单例深挖显示 `pool_B_only` 直接给出正确答案。
题目有捷径，测的不是比较；加上 logits 间距仅 1–2、n=12，结果全是噪声。

**教训：任何"需要两块"的题目，必须加 only_A / only_B 对照臂，否则不知道测的是什么。**

## 五、可行性结论

| 能力 | 可行 | 依据 |
|---|---|---|
| 未旋转存 K、按目标位置旋转 | ✅ | 误差 0.000 |
| 从长上下文池里取块并重紧凑 | ✅ | Δlogits 0.125 |
| 查找类：池化服务，质量不降 | ✅ | 12/12 = 12/12，快 3–5× |
| 推理类：池化服务 | ✅ | 18/20 vs fresh 20/20 vs full 14/20 |
| 显存（1.7K 上下文，fp32 存 K_pre） | ✅ | 峰值 4.70 GB / 8 GB |

## 六、待改进

1. **K_pre 用 fp32 暂存太占内存**（本例翻倍）。应存 bf16，旋转时升 fp32。
2. 未测更大上下文（4K/8K）；fp32 K_pre 会先撞显存墙。
3. 池化与联合 prefill 的差距（18/20 vs 20/20）是否稳定，需更大 n。
4. 所有"需要多块"的题目必须配 only_A / only_B 捷径检测，否则结论无效。
