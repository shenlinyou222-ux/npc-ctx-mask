# 范式：空白缓存块的替换，就是子智能体向主智能体传递信息的方式

## 陈述

> 主智能体对子智能体只需**下命令**，然后**分支出去**获取独立上下文；
> 子智能体把结论**写回一个预留的空白缓存块**——这就是信息传递本身。

两条路径，**方向和载体都不对称**：

```
              命令（文本，很小）
   主智能体 ──────────────────────> 子智能体
      │                                │
      │                                │  在自己的独立上下文里 prefill
      │                                │  生成结论
      │                                │
      │   结果（K/V，写进预留的空块）   │
      │<───────────────────────────────┘
      │
      └─ 解除掩码 → 之后的 token 才读得到
```

| | 下行（命令） | 上行（结果） |
|---|---|---|
| 载体 | 文本 | **缓存块** |
| 作用位置 | 子智能体的上下文 | 主序列的预留空位 |
| 代价 | 一次 prefill | **只对 [0,P) 做 prefill** |
| 主智能体的前缀 | 不变 | **不变** |

## 为什么"空白块"是关键

块在被填写之前**没有内容**——它不占语义，也不进入注意力。所以：

- 主智能体可以在块空着的时候继续 decode（**已测**：延迟回答 q2 ✔ → q1 ✔）
- 多个块可以并存，一个一个填（**已测**：遮两段只留一段 → 恰好只剩那题可答）
- 填写用的是**只对槽位之前缓存**的 prefill，不需要重算前缀或后缀（**已测**：incremental 6/6 = inline 6/6）

这三条合起来，就是"传递信息"能做到零重算、零干扰的原因。

## 已验证的部分

| 环节 | 证据 |
|---|---|
| 空白块填之前读不到 | canary 0/8；empty 臂 0/6（且会把实体名答对、编码编成 `12345`） |
| 填入后读得到 | 单槽位 20/20；NS=3 12/12；NS=5 20/20 |
| 只用 [0,P) 的缓存做 prefill | incremental 6/6，与整条重算的 6/6 相同 |
| 多个块分别填写、分别解除 | 9/9 · 3/9 · 0/9 |
| 填写不影响已有上下文 | 短上下文历史 12/12 持平（槽位 0→8） |
| 块空着时主智能体可继续工作 | 延迟回答：先答 q2 ✔，解除后答 q1 ✔ |

## 一句必须说准的话

当前实现里，子智能体产出的是**文本**，由**引擎侧把这段文本重新 prefill 成 K/V**，
再换回空块。所以载体是"在该位置的 K/V"，而不是"从子智能体那边原样搬过来的 K/V"。

两者不等价：搬运子智能体原始 K/V 要求它生成时就落在目标位置（我们试过，位置对不上）；
重新 prefill 则只是在该位置重算一遍——**代价只有 len(answer) 个 token**，
前缀和后缀都不重算。

已验证：swap 26/27、inline 27/27、empty 0/27（见 `docs/multislot.md`）。
