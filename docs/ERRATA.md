## 多槽位的两条错误路线（本轮新增）

| 做法 | 结果 | 原因 |
|---|---|---|
| 用 `position_ids` 覆盖，把子智能体的生成硬放到槽位位置 | **swap 0/5**（同脚本 full 5/5） | HF 里显式 `position_ids` 与 KV cache 不兼容，拼进去的 K/V 不可用 |
| 把子智能体前缀填充到与槽位起点等长，再让它生成 | **n=0/160** | 填充放在指令之前，模型改为总结共享前缀，不产出结论 |

**正确做法**：子智能体在自己上下文里**先答完**，把答案文本**回填**到槽位位置，再解除掩码。已验证 NS=3 **12/12**、NS=5 **20/20**，空槽位 0/12 与 0/20。

## 关于 V4.1-Flash 的 890 B/token

**已核对**：arXiv 2609.19969（2026-09-17）原文明确写明 "reduce its global KV cache footprint (always in HBM) to 890 bytes per token"，靠 **CSA2 跨层复用 + FP4 KV** 达成，约为 V4-Flash 的 1/4。此前"未能独立推导"的疑虑可以撤销——它就是官方口径，且有架构解释。

## 本工作的核心设想已被公开工作完整覆盖（2026）

**arXiv 2607.27090 — InferScale（2026-07，v2 2026-09）** 已实现并证明：

| 我们的设想 | InferScale |
|---|---|
| 存储时不写位置，注意力时施加 | **Chunked RoPE**：在 `apply_rotary_pos_emb` 前拦截，缓存未旋转 key |
| 选中块紧凑化 | 注入时分配**连续虚拟位置 0…m−1** 并在注入时旋转 |
| 跨块条件化丢失 | **Context-Window Encoding**：每事实连同前 w 轮一起编码，只缓存目标 KV |
| KV 写进缓存而非 prompt | 通过 **vLLM KV-connector** 直接写入分页缓存，不改引擎、不微调 |
| 精确性 | **Theorem 1/3**：KV 注入与 prompt 注入在 query 位置**精确等价** |

结果：k=400 时 TTFT 25 ms vs Mem0 343 ms（13.9×），LoCoMo 60.3% vs 63.3%。

**同期的其他覆盖**：Leyline（策略驱动的区间移除/替换 + RoPE 校正）、Kamera（位置无关复用 + 多跳退化 + 低秩补丁）、RelaxKV（查询引导的选择性重算）、RoPERelay（选中后的位置几何）。

**结论**：本仓库原本主张的"块池 + 选择 + 紧凑化 + 按需重建"在 2026 年已被多篇工作分别并完整覆盖，
**不能再作为新机制主张**。本仓库剩余的价值只剩：

1. 权限可见性（内容留在缓存但某次请求不许读）——上述工作都是"检索到什么就注入什么"，没有访问控制语义；
2. 多智能体实时返回写入预留空位——上述工作注入的都是离线预计算的事实；
3. 审计与 fail-closed 的工程要求。


## 统计口径

- 「泄漏」= 复现了受限版本的 gold；**未检测**是否输出了受限文档中的其它内容，也无人工审核；
- 多数实验 n ≤ 60，未报置信区间；
- 判分在不同脚本中不一致（完整子串 vs 前缀匹配），是本次多数数字偏差的根源。**统一判分**已列入 ROADMAP。

## 追加：两条"遮蔽有代价"的结论是块偏移 bug 的假象（2026-10-28 重跑）

| 实验 | 旧报告 | 修正后 | 原因 |
|---|---|---|---|
| Baroque（51% 遮蔽） | A 15 → M **9** | A **9/10** = M **9/10** | 块号偏 3 token，遮蔽遮到相邻块，把可见段落也遮了 |
